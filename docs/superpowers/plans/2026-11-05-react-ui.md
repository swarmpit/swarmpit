# Swarmpit React UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Swarmpit's existing functionality in a TypeScript React UI and leave durable upstream-update instructions for future agents.

**Architecture:** Preserve the Clojure backend and legacy UI. Add a Vite frontend at /react/index.html, retain hash routes and existing HTTP/SSE contracts, and keep backend merge points small. Work on react-ui based on upstream/master, preserving bootstrap main.

**Tech Stack:** Current stable React, TypeScript, Tailwind CSS 4, shadcn/ui, TanStack Query, maintained hash routing, native fetch/EventSource.

**Spec:** docs/superpowers/specs/2026-11-05-react-ui-design.md (approved by user, with additional required persistent agent instructions).

## Global Constraints

- Preserve authorization, validation, data, API methods, optional statistics, existing deployment and full functionality.
- No database migration, backend rewrite or raw JSON replacement forms.
- Keep legacy frontend available until React parity and real Docker checks pass.
- Do not stage, commit, push, merge or publish without user authorization; plan commit steps are deferred.
- Use filesystem MCP for file operations, dry-run edits before applying, rg for content search, Context7 for current dependency documentation.
- Do not run destructive checks against an existing production Swarm.

## Review Focus

- Login token already includes Bearer: test unchanged forwarding, empty bodies, session-boundary versus registry 401.
- Consumed SSE tokens: test fresh token/reconnect and route-change/logout cleanup.
- Background refresh during editing: forms must retain dirty state and submit full domain payloads.
- Viewer/admin/owner permissions: cover UI capabilities and retain backend authority.
- Upstream update conflicts: preserve both histories, reject automatic merge, and keep contract/parity records current.
