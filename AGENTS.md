# Swarmpit React fork — instructions for future agents

## Scope and architecture

Read this file before changing the repository. Read [docs/UPSTREAM_UPDATES.md](docs/UPSTREAM_UPDATES.md) before any upstream sync, and [docs/UI_PARITY.md](docs/UI_PARITY.md) before adding/removing UI behavior. Approved design: [docs/superpowers/specs/2026-11-05-react-ui-design.md](docs/superpowers/specs/2026-11-05-react-ui-design.md).

This is a public fork of https://github.com/swarmpit/swarmpit. The product must retain Swarmpit's functionality and backend; only its UI is being rebuilt with React, strict TypeScript, Tailwind CSS **4**, current shadcn/ui and TanStack Query. React code lives in frontend/. Legacy code remains in src/cljs/ and is the behavior reference until each parity item is verified. Do not report a static build or a dashboard as full feature parity.

## Non-negotiable invariants

- Keep backend authorization, request validation, error handling, database migrations, Docker/agent behavior and optional InfluxDB integration intact. Never move authorization into the client.
- Trace old page → request/spec → handler → mapper before changing a flow. Source code wins over stale comments in CLAUDE.md.
- POST /login returns a complete Bearer authorization value. Forward it unchanged. Version/bootstrap is GET /version, not /api/version. Retain first-admin initialization and real logout/revocation.
- SSE /events consumes a fresh /slt token on every connection. subscription is base64 EDN with legacy handler/params, not JSON. Close old streams and retries on navigation/logout.
- Preserve separate command/entrypoint and labels/containerLabels, image tags and digests, optional mount host for tmpfs/anonymous volumes, stored stack compose/history, role/owner restrictions and immutable services.
- Service updates replace explicitly submitted containerLabels/sysctls maps, including empty arrays for removal. Preserve omitted fields for older clients, generated stack metadata and unrelated raw Docker fields; keep the backend and disposable integration regressions.
- Forms must preserve dirty values across query refreshes. Never auto-retry destructive mutations. Confirm destructive actions and show backend failures.
- Keep the sidebar brand as Swarmpit with the application version from the version field returned by GET /version; instanceName belongs in the document title and docker.engine is the Docker version. Preserve the brand/version tooltip and accessible website link in the collapsed sidebar. The sidebar brand is a native same-tab link to https://swarmpit.io/ with no hover/pressed background or text-color effects; retain its keyboard focus ring. Breadcrumbs use the generated shadcn Breadcrumb/List/Item/Link/Separator components with router links to the overview and current section. The root link is Overview; show it once without a separator on the home page. Keep the current section clickable and mark exact current routes with aria-current. The footer user item opens a shadcn dropdown with user information, a theme radio submenu, account settings and sign-out. Follow the actual sidebar-08 NavUser composition with Avatar identity in both trigger and menu header. Group Swagger API and Classic UI as secondary navigation at the bottom of SidebarContent above the footer user panel, using the shadcn NavSecondary pattern. Keep Swagger API as a native link to /api-docs that opens a new tab for every signed-in role; never route it through the SPA. Classic UI uses the native same-tab /?ui=classic link. Mount sidebar tooltip content only in the collapsed desktop rail; hidden tooltip layers can intercept mobile Escape.
- Use Hugeicons for UI/button/menu/navigation icons: named data imports from @hugeicons/core-free-icons rendered by HugeiconsIcon from @hugeicons/react with strokeWidth 2 and existing sizes. Keep decorative icons aria-hidden and preserve accessible button labels, disabled state, spinners and reduced motion. components.json sets iconLibrary=hugeicons; do not reintroduce Lucide when adding/updating shadcn controls. Keep the original Swarmpit logo SVG. Every visible application action button and tab includes a meaning-specific decorative Hugeicon in its idle state; Action requires explicit icon data, and Submit uses a save icon by default or a caller-provided icon. Pending state replaces the action icon with one reduced-motion spinner; keep confirmation/cancel/close controls and dynamic chart legend toggles covered. Every rendered badge includes a decorative, meaning-specific Hugeicon beside its visible label, including unknown states; Live keeps its connection-state icons. Mode/role/count metadata badges retain the neutral muted surface and foreground text instead of a solid olive fill.
- Keep the original Swarmpit palette in frontend/src/styles.css: purple #65519f with #957ed1/#362870, olive #8b9f51, and dark-mode purple #b39ddb/olive #aed581. Use semantic theme tokens for component, status and chart colors; retain accessible contrast.
- Build all metric charts with the generated shadcn/ui chart primitives and Recharts through frontend/src/features/dashboard/chart.tsx. Keep interactive area history charts, CPU/memory/storage donuts, manager/worker counts and separate node/service CPU/memory charts on Overview. Donuts start at 12 o’clock and progress clockwise (startAngle 90, endAngle -270). Chart colors derive from the purple/olive theme; utilization uses semantic warning at >=75% and destructive above 90%. Retain time ranges (last hour by default), zoom/pan/reset, series toggles stable across snapshot reordering and PNG export. Preserve timestamp alignment, null gaps, backend-provided %, vCPU and MiB units, accessible tooltips/legends and the semantic chart palette. Verify generated chart selectors against the installed Recharts DOM; tick text currently uses recharts-cartesian-axis-tick-value, and the older tick descendant selector leaves dark axes at hardcoded #666. Do not replace these with hand-drawn SVG charts.
- Apply the saved swarmpit.theme preference synchronously in the HTML head before the app paints; keep critical canvas colors, color-scheme and theme-color aligned with runtime light/dark/system semantics, including unavailable storage. Session loading must retain the real inset sidebar/header/content frame and route-shaped shadcn skeletons while protected outlets, requests and account actions remain gated. Keep the authenticated shell bounded to the dynamic viewport: rounded inset and header stay fixed, and only the inner #main-content pane scrolls. Keep its flex ancestors shrinkable, preserve inset margins/corner clipping, and leave login/body scrolling independent. Reset the pane on pathname navigation, not on live updates or same-page interactions; preserve skip navigation, portalled controls and nested table/editor scrolling.
- Every ResourceTable requires an explicit sortBy getter for its primary visible identifier. Sort copied filtered rows A–Z with case-insensitive natural number ordering; keep each row's fields/actions together and never mutate query data or request payloads. Remote catalog sorting applies within the fetched page. Preserve chronological logs/history/chart samples and editable draft ordering.
- Use the shared Loading component and shadcn Skeleton for initial data loads (content, table and chart layouts). Distinguish disabled queries and empty/error states from pending requests; keep cached data visible during background refetches. Keep skeletons decorative with named loading statuses. Use steady bg-muted placeholders without pulse/shimmer animation; preserve reserved dimensions to avoid layout jumps. Static placeholders also respect reduced-motion preferences.
- Use shared CodeField for YAML Compose editing/viewing (generated service, stack stored/reconstructed/history and engine comparisons); keep read-only permissions, exact raw content, dirty drafts, source/restore operations and original downloads/payloads. Pass disabled explicitly while mutations/source loads are pending, and keep fallback/editor/Skeleton heights aligned. Configs retain ConfigValueField as the Value-specific entry to this same syntax editor on create and detail. Keep YAML/JSON/plain-text selection presentational, use semantic theme colors, and preserve raw UTF-8/base64 payloads, binary file uploads, required value validation, lazy-load drafts/focus and Docker config immutability. Do not convert/reformat submitted editor values or add persistence/transmission outside the existing resource APIs.
- Use shadcn Select for fixed-choice dropdowns. Keep Choice's empty/default encoding internal and forward the original values to API payloads. Preserve disabled items and pass disabled state to portalled controls explicitly when a form fieldset is disabled. Keep provider queries mounted outside lazy menu content; retain editable free-text suggestions where custom values are supported.
- Use shared NodeCards/NodeResourceCharts for the full Nodes page, Overview pins and node detail; preserve actual CPU/memory/storage gauges, capacities, ready/down handling, OS and role/search filters. Storage is decimal, memory binary. Pinned services and shared service tables retain published ports and update/rollback status precedence through serviceDisplayState. Hide genuinely empty pin/history sections instead of rendering repeated empty cards.
- Task logs belong in their own tab; preserve legacy log=1 links, supported-driver checks and exact task filtering. Keep stack page/header/tabs mounted during initial loads with matching property/editor Skeleton layouts; preserve dirty drafts on refresh. Network maps use actual connected services and attachment aliases, never fabricated task/IP relationships.
- Preserve the original license and attribution. No production data/destructive Swarm testing.

## Upstream updates

Follow docs/UPSTREAM_UPDATES.md in order. Use normal merges preserving upstream history. Never reset the custom branch to upstream, force-push, blindly accept one side of conflicts, overwrite frontend/, or merge the unrelated bootstrap main branch.

For every update: record old/new upstream SHA; inspect changed route/spec, auth, event, handler and mapper contracts; port changed/new UI behavior into React; update the parity checklist and baseline; run the required checks; review the complete merge diff. Receiving upstream commits does not port upstream UI changes automatically. Do not auto-merge or auto-deploy updates.

## Tools and verification

Use the configured filesystem MCP for reads/writes when available, read_multiple_files for independent reads, and edit_file with dryRun before applying edits. Use rg for content searches. Use Context7 resolve-library-id then query-docs for current library/API/CLI documentation. Use installed dependencies and existing helpers; keep changes at the responsible layer.

Frontend checks: npm --prefix frontend ci; npm --prefix frontend test; npm --prefix frontend run typecheck; npm --prefix frontend run build. Backend changes: lein check and lein test; Docker/mapper changes additionally require the documented disposable integration suite. Packaging changes require building Dockerfile.react and verifying /react/index.html plus streamed /events against a disposable Swarm. Missing runtimes/credentials are unverified checks, never passing checks.

Local visual review uses the existing isolated environment documented in dev/review/README.md. Use its guarded start/seed helpers; preserve the review account, CouchDB, Docker-in-Docker and InfluxDB volumes. Keep agent callbacks aligned after replacing the app container. Populate graphs with real collected metrics, never invented production responses.

Never stage, commit, push, publish, merge PRs or alter repository settings unless the user authorizes it. Use Conventional Commits when authorized. Do not expose credentials in commands, logs or documents.
